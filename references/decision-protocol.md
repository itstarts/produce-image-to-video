# 决策交互协议

## 何时提问

只在选择会明显改变内容、视觉、成本、时长、平台兼容性或用户工作量时提问。典型门禁包括：

- 目标观众、发布平台、画幅和时长
- 旁白方向和语气
- 视觉风格、固定角色或产品形象
- 风格样片、代表性分镜和旁白锁定
- 外部图生视频平台与保存位置
- 静态 HyperFrames、外部片段或混合制作模式
- 对明显瑕疵选择接受、重做或换方案
- 字幕风格、音乐、音效和最终输出

不要让用户决定临时目录、FFmpeg 编码细节、抽帧算法、哈希检查或不改变语义的安全技术处理。

制作模式必须在动作需求和分镜方向清楚后询问。说明三类方案在真实动作、稳定性、成本和用户操作量上的差异；不要因为用户提到某种媒体风格就自动选择外部图生视频。

## 提问格式

每轮只问 1～3 个当前必要问题。每个问题：

1. 用一句话说明要决定什么。
2. 提供 2～3 个互斥方案。
3. 把有依据的方案标记为“推荐”。
4. 每个方案说明结果或取舍。
5. 明确用户可以直接给出自己的选择。

示例：

```text
这条视频更适合哪种叙事语气？

A. 自然克制（推荐）：信息清晰，适合大多数知识和故事内容。
B. 轻快幽默：节奏更快，但可能削弱严肃信息。
C. 电影预告：情绪强，但需要更密集的镜头和声音设计。

推荐 A，因为当前目标是让观众快速理解核心观点。你也可以直接描述自己的语气。
```

## 等待规则

- 推荐不等于批准。关键门禁未确认时停止在当前阶段。
- 用户自定义方案优先；先检查它是否与已确认目标、素材或工具能力冲突。
- 有冲突时说明可验证依据、影响和替代方案，不迎合错误前提。
- 用户选择后，只把最终方案写入项目状态；不要保留已推翻方案制造歧义。
- 对细小、局部、可逆且不改变内容语义的技术细节可以依现有模式处理，并在交付时说明。
